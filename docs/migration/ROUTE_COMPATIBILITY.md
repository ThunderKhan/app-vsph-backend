# Fastify / frozen Express / Next.js route compatibility matrix

Verified reference: `ThunderKhan/vsph-control-center@3b3a1535873aa0517aea41da32a407f3d9680547`.  
Frontend: `ThunderKhan/app-vsph-frontend@65df1f9878ac7cc60d090befe6a3bb2947a49c90` (branch `migration/remaining-frontend-parity`).  
Destination: `ThunderKhan/app-vsph-backend@migration/fastify-backend-parity`. Last audited 2026-11-23.

Status is **source-wired**, not live/staging certified. `Wired` means a Fastify handler and backing adapter are committed but execution / live DB compatibility is **unverified**. `Partial` means missing an original case. `Blocked` means deliberately not enabled for security. `Pending` means the handler has not been ported. All paths below must remain unchanged for the Next.js backend proxy.

**Observed frontend contract issues:** Portal-login Next proxy forwards a temporary setup token but not the previous portal cookie, so silent backend rotation of that old token is not possible. The frozen frontend's product-record create interface lacks an atomic tenant+idempotency guarantee; POST records must not be enabled without a reviewed DB transaction. The original employee temporary-credential login and the independent Music/Outreach client receivers have no equivalent working Fastify implementation yet. Role-navigation checks in Next are not server authorization.

**Module notation:** Files in the module column are implementation targets (for Pending rows) or committed source (for Wired/Partial). `Next consumer` names an observed handler or SSR helper, not proof of a successful live request. Non-UI provider/worker endpoints have no Next consumer. SQL code and original migration manifest remain the source of transaction and authorization semantics.

- 171 explicit legacy HTTP entrypoints (including dynamic action families); 59 source-wired, 2 partial, and 110 blocked/pending. Dynamic action families are not independently certified; source-wired does not imply live SQL/provider acceptance.
- A route is not complete until its exact response schema, error code, cookie semantics, SQL authorization and role/tenant-negative cases pass with the intended frontend proxy. Status intentionally excludes mere presence of a TypeScript handler.
- The original Express source has additional service-only worker commands, GitHub sync, outbox delivery and SQL helper functions **not exposed as HTTP endpoints**. They require separate worker inventory/acceptance, not fictitious HTTP rows.
- No Prisma schema or production migrations should be inferred from this matrix. Confirm checked-in SQL history against an approved isolated staging snapshot before mapping ORM models or privileged RPCs.
- This matrix is based on observed original route registration and Next route files; dynamic routes require a later full automated trace to rule out hidden combinations and test overlays. It is **not** certification of full live coverage.
